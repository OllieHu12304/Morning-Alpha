# Morning Alpha 期中報告演講草稿

> 建議總長：13～14 分鐘  
> 簡報：約 9 分 45 秒  
> 實機操作：約 3 分 30 秒  
> 畫面切換與緩衝：約 45 秒

## 報告前準備

1. 在 repository 根目錄執行：

   ```bash
   python3 start.py
   ```

2. 確認 `http://127.0.0.1:5050` 可以顯示 Dashboard。
3. 預先完成一次 Pipeline，不要把資料下載時間算進現場 demo。
4. 在 My Watchlist 加入一間有相關新聞的公司。
5. 另開一個 Terminal，保留最近一次成功 Pipeline 的輸出。
6. 關閉 `.env` 或任何可能顯示密碼的視窗。

## 第 1 頁｜Morning Alpha（約 25 秒）

大家好，我今天要介紹的專案是 Morning Alpha。它是一個科技與財經新聞整合分析系統，目的是把原本分散在不同網站的新聞、上市公司資料和市場資訊，整理到同一個 Dashboard 中，讓使用者可以更方便地搜尋與追蹤。

## 第 2 頁｜我想解決什麼問題？（約 40 秒）

我一開始觀察到，科技新聞、財經新聞、公司公告和股票資料分散在不同網站。使用者不只要重複切換頁面，也很難直接知道某則新聞可能和哪家公司有關。因此，我希望把這些資料先透過 Python 收集，再整理成一個可以搜尋和閱讀的網頁。

## 第 3 頁｜Morning Alpha 可以完成什麼？（約 45 秒）

目前使用者可以集中閱讀五個來源的新聞與公告，也可以依照來源、分類或公司搜尋。系統會統計熱門關鍵字，提供公司價格和部分財務資料，也能建立自選公司清單，閱讀追蹤公司的近期新聞。資料更新則可以直接從 Dashboard 按鈕執行。

## 第 4 頁｜資料從哪裡來？（約 45 秒）

目前的新聞來源包括 TechNews、中央社、自由時報、Yahoo股市和證交所重大訊息。TechNews 是一般 HTML 網頁，所以使用 BeautifulSoup 解析；三個媒體來源使用 RSS；證交所的公司、公告、價格和財務資料則主要是 JSON 格式。不同格式最後都會轉成專案共用的資料結構。

## 第 5 頁｜一則新聞如何進入 Dashboard？（約 60 秒）

這張圖是整個專案最重要的流程。Python 先使用 Requests 下載外部資料，再使用 BeautifulSoup、XML 或 JSON parser 解析。接著 Pandas 負責整理欄位和時間，MySQL 負責永久保存。網頁不會直接連線 MySQL，而是向 Flask API 請求 JSON，最後由 JavaScript 把資料顯示在 Dashboard。這些技術不是各自獨立，而是接力處理同一筆資料。

## 第 6 頁｜不同網站如何共用流程？（約 45 秒）

不同網站的欄位名稱和結構不一樣，所以我為每個來源建立 Adapter。可以把 Adapter 想成翻譯員：它把 HTML、RSS 或 JSON 翻譯成相同的 News Record，例如來源、發布者、文章 ID、標題、時間和網址。如此一來，後面的 Pandas 和 MySQL 不需要知道每個網站的特殊格式。

## 第 7 頁｜資料如何避免重複？（約 50 秒）

這裡我沒有只使用標題去重，因為兩家媒體可能剛好使用相同標題，但仍然是兩篇不同文章。系統主要使用正規化網址，以及來源加文章 ID 阻止相同文章重複寫入。如果不同媒體報導同一事件，系統會保留每一篇，只在畫面中把它們分組。

## 第 8 頁｜一次更新完成哪些工作？（約 45 秒）

完整 Pipeline 原本有九個步驟，這裡把它簡化成四個階段：先取得與保存新聞，再同步公司、價格和財務資料，接著建立公司關聯、晨報和關鍵字，最後更新 Dashboard 所需資料。使用者現在可以從網頁按下立即更新資料，不需要記住多個 Python 指令。

## 第 9 頁｜實際操作 Morning Alpha（約 15 秒）

接下來我會切換到實際畫面，示範新聞搜尋、自選公司、公司市場資料，以及資料更新入口。

# 實機操作流程（約 3 分 30 秒）

## Demo 1：Latest News（約 50 秒）

1. 捲動到 Latest News。
2. 在搜尋框輸入一間公司名稱。
3. 示範來源或公司篩選。
4. 指出標題、來源、分析分類、公司標籤和發布時間。

講法：

> 新聞資料是從 API 載入後由 JavaScript 顯示。搜尋和篩選是在目前的新聞資料中進行，因此不需要每次重新爬取網站。

## Demo 2：My Watchlist（約 50 秒）

1. 使用搜尋欄輸入股票代號或公司名稱。
2. 加入或展示已加入的公司。
3. 指出追蹤晨報的相關新聞。

講法：

> 追蹤清單保存的是公司 ID，不是只有畫面文字。系統再透過新聞和公司的關聯，找出追蹤公司近期相關文章。

## Demo 3：Company Market Data（約 55 秒）

1. 選擇一間有資料的公司。
2. 指出最新交易日、收盤價與價格圖。
3. 指出季度財務摘要。

講法：

> 這些是證交所盤後和財務摘要資料，不是即時行情，也不能直接當成投資建議。

## Demo 4：Pipeline（約 55 秒）

1. 捲動到 Pipeline 執行紀錄。
2. 指出「立即更新資料」按鈕。
3. 展示最近一次成功紀錄及九個步驟。
4. 不必等待完整 Pipeline 執行完成。

講法：

> 這個按鈕會在後端啟動和終端指令相同的 Pipeline。因為現場下載外部網站可能需要時間，我這裡用最近一次成功紀錄說明結果。

## Demo 失敗備案

如果 Dashboard 無法開啟：

> 目前本機服務沒有成功連線，因此我改用簡報中的流程與歷史畫面說明。這也反映本專案目前仍是本機開發版本，需要 Flask 和 MySQL 同時運作。

如果新聞來源 timeout：

> 外部網站偶爾可能逾時，因此系統加入最多三次 retry，並分開保存每個來源的成功與失敗狀態。單一新聞來源失敗時，其他來源仍可繼續。

如果資料日期不是今天：

> 這裡顯示的是來源實際提供的最新交易日。系統會警告資料延遲並回補近期缺漏日期，但不會把 API 成功誤稱為資料一定最新。

## 第 10 頁｜從爬蟲發展成完整系統（約 55 秒）

專案最早只有 TechNews 爬蟲，接著建立共同新聞格式與統一 Pipeline，讓不同來源可以一起處理。之後加入 Flask API、公司和市場資料，才逐漸成為可操作的 Dashboard。最後的收斂階段則處理來源不平衡、股價缺漏和事件觀察等實際使用問題。

## 第 11 頁｜幾次重要問題與修正（約 75 秒）

第一個問題是「中華電」曾同時比對到中華、華電和中華電，後來改成完整名稱優先並排除重疊結果。第二個問題是 TWSE 公告數量曾遠高於媒體新聞，所以 Dashboard 改成每個來源最多取近期 60 篇，但 MySQL 仍保存完整資料。第三個問題是最新價格快照延遲時可能漏掉交易日，因此加入近期缺漏日期回補。這些修改都不是單純增加功能，而是從真實資料中找出問題再修正。

## 第 12 頁｜目前限制（約 60 秒）

目前系統只有五個新聞取得來源，主要涵蓋 TWSE 上市公司，也沒有即時行情。公司辨識、新聞分類和事件分組是規則式方法，所以仍可能誤判。晨報不是生成式 AI 摘要，也沒有讀取文章全文。新聞附近的價格變化只能表示時間上的關聯，不能證明新聞造成股價變化。專案目前適合本機學習和個人使用，還不是正式投資平台。

## 第 13 頁｜未來發展方向（約 45 秒）

近期會優先改善資料涵蓋率、公司辨識和歷史價格完整性。中期可以加入更多市場、帳號和自動晨報推播。長期如果要公開使用，還需要登入權限、安全機制和正式部署。我認為目前最重要的成果，是完成了從資料取得、整理、保存，到 API 和網頁呈現的完整流程。以上是我的報告。

# 老師可能提問

## 為什麼使用 Pandas？

因為多個來源轉成共同欄位後，Pandas 很適合處理時間轉換、排序、分組與統計；永久資料則交給 MySQL。

## 為什麼需要 Flask API？

瀏覽器不應直接連線 MySQL。Flask 負責查詢資料、轉成 JSON，再安全地提供給前端。

## 為什麼不用標題去重？

相同標題可能來自不同媒體，稍微不同的標題也可能是同一事件。因此相同文章使用網址與來源文章 ID 去重，同事件則分組但不刪除。

## 這個專案有使用 AI 嗎？

目前沒有生成式 AI。中文關鍵字使用斷詞與統計，公司辨識、分類和事件分組主要是規則式方法。

## 新聞可以預測股價嗎？

目前不能。系統只顯示新聞附近的價格變化，沒有控制大盤、產業、財報等其他因素，因此不能宣稱因果或預測。

## 為什麼選擇 MySQL？

新聞、公司、股票、價格和追蹤清單彼此有明確關係，關聯式 Database 適合使用 key、JOIN 和 UNIQUE constraint 管理這些資料。

## 為什麼 Dashboard 每來源最多 60 篇？

因為 TWSE 公告數量遠高於媒體新聞，若直接混在一起會讓分析失去平衡。這只限制 Dashboard 顯示樣本，MySQL 仍保存完整資料。

## 其他人能不能直接使用？

可以 clone 後在本機設定 Python、MySQL 和 `.env` 使用，也可以選擇 Docker。但目前沒有帳號、安全及正式伺服器設定，不建議直接公開到 Internet。
